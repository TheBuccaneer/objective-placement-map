# Data dictionary

This document describes the files consumed and generated by the frozen
objective-placement analysis.

## Provenance

- measurement commit: `e54128a613e7d6adc46150c020b26b6f98a4c0a2`
- pinned source snapshot: `data/source-snapshots/energy-e54128a613e7/`
- canonical input count: **28 CSV files**
- canonical configuration count: **918 configurations**
- session table size: **4590 configuration-session medians**
- canonical decision cells: **51 workload-size/shape cells**
- generated output count: **37 CSV files**
- generated figure count: **5 PNG files**

## Statistical units

The independent session is the primary statistical unit. Ten repetitions
within one session are aggregated before cross-session inference. The
canonical decision cell is `(workload, problem size or Conv2D shape)`.

Within each cell the analysis compares the best available Intel thread
configuration, the best available AMD thread configuration, the RTX 3090,
and the RTX 5060 Ti for runtime, energy, EDP, regret, and Pareto membership.

### Input families

- `*_sessions.csv`: session medians used for robustness and holdout analysis.
- `*_all_sessions.csv`: harmonized session-level tables.
- `*_config_summary.csv`: per-configuration summaries across sessions.
- `*_envelopes.csv`: best platform/configuration values per objective.
- `*_placement*.csv` and `*_leaders.csv`: objective leaders and conflict labels.
- `*_pairwise.csv` and `*_cross.csv`: pairwise or cross-platform comparisons.

## Energy-domain interpretation

- GPU energy is NVML device/board energy for the selected execution scope.
- CPU energy is RAPL package energy; DRAM is handled separately where available.
- `gpu_resident` excludes allocations, initialization, and host/device transfers.
- Logical byte counts are semantic anchors, not measured physical memory traffic.
- CPU/GPU energy-domain comparisons must retain these documented boundaries.
